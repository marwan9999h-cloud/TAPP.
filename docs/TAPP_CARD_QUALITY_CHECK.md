# TAPP Card Quality Check & Pre-Delivery Checklist

هذا الدليل يفصل بوضوح بين الفحوصات المؤتمتة (التي ينفذها السكربت والـ Build في بيئة التطوير)، وفحوصات المتصفح، وفحوصات الموبايل الفعلي، وفحوصات الكارت المطبوع وشريحة الـ NFC قبل تسليم أي كارت جديد لعميل.

---

## 1. التصنيف الصريح لحالة التحقق (Verification Separation)

| الطبقة | المسؤولية | الحالة في بيئة التطوير الحالية |
| :--- | :--- | :--- |
| **Automated Checks** | `bun run lint && bun run build && bun run check:brands` | تنفَّذ تلقائياً في الطرفية وتتحقق من السيريلات والـ vCard وفك تشفير الـ SVG وPNG 1024px. |
| **Browser Verification** | فتح `/` و`/guide` و`/atlas` و`/sovi` و`/bymarcos` ومسار 404 في متصفح فعلي (Desktop & Mobile viewport) | **لم تُختبر في متصفح فعلي داخل بيئة Linux الطرفية** — مطلوبة قبل الإطلاق أو بعد أي تعديل بصري. |
| **Real-Device Mobile Test** | اختبار الـ Web Share sheet، نسخ الرابط، تنزيل واستيراد ملف `.vcf`، ومسح QR بكاميرا iOS وAndroid | **مطلوبة على جهاز حقيقي** — بيئة السيرفر لا تحاكي نافذة مشاركة النظام أو تطبيق Contacts. |
| **Physical Card & NFC Test** | برمجة شريحة NTAG، اختبار مسح الكارت المطبوع، والتحقق من الوضوح والقص والتغليف | **مطلوبة بعد الطباعة والبرمجة** قبل التسليم للعميل. |

---

## 2. قائمة فحص الصفحة الرقمية والبيانات (Digital & Data Checklist)

1. **ثبات الدومين الرسمي (Canonical URL):**
   - تشغيل `bun run check:brands` أو `npm run check:brands` للتأكد أن الدومين المولّد لكل براند يطابق `https://tapp-link.vercel.app/<slug>` ولا يظهر أي رابط محلي (`localhost`) أو رابط معاينة مؤقت.
2. **صلاحية الروابط الخارجية:**
   - التحقق من عدم وجود روابـط ناقصة أو نصوص تجريبية (`TODO` / `example.com`) في ملفات البيانات (`src/data/`).
   - مراجعة فتح كل رابط خارجي (Spotify / Anghami / Instagram / WhatsApp / Facebook / Maps) والتأكد من وصوله للحساب الصحيح.
3. **قاعدة Save Contact (`.vcf`):**
   - التأكد من إخفاء زر `Save Contact` على الصفحات التي لا تملك بيانات تواصل مباشرة مؤكدة (مثل `ATLAS` و`SOVI` حالياً).
   - التأكد على الصفحات المؤهلة (مثل `BY MARCOS`) من وجود رقم دولي صريح يبدأ بـ `+` أو إيميل أو عنوان حقيقي، مع خلو الحقول الفارغة من أي قيم مضللة وعدم استعارة بيانات TAPP نفسها.
4. **ثبات الـ SEO والمشاركة الاجتماعية (Social Preview):**
   - بعد تشغيل `bun run build`، التأكد من خروج ملفات الميتاداتا المسبقة (`dist/guide/index.html`, `dist/atlas/index.html`, `dist/sovi/index.html`, `dist/bymarcos/index.html`, `dist/sitemap.xml`).
   - التحقق من وجود صور `public/og/*.png` وعدم تلفها.
5. **دليل الاستخدام (`/guide`):**
   - فتح `/guide` والتبديل بين العربية (`dir="rtl"`) والإنجليزية (`dir="ltr"`) وفتح وإغلاق أسئلة الـ FAQ على شاشة موبايل (مثل 390px) لضمان عدم وجود تمرير أفقي أو تداخل نصوص.

## 3. قائمة فحص رمز الـ QR (QR Readiness Checklist)

1. **مطابقة الرابط المشفر:**
   - تشغيل `bun run check:brands` للتحقق بالبكسل (عبر `jsQR`) من أن كلاً من ملف `SVG` وملف `PNG (1024x1024)` يفك تشفيرهما إلى نفس الرابط الرسمي للبراند بدقة.
2. **معايير الطباعة المادية:**
   - استخدام ملف الـ **SVG** في التصميمات الطباعية (Illustrator / Figma / Print house) أو ملف الـ **PNG (1024×1024)** عند الحاجة لصورة نقطية عالية الدقة.
   - الحفاظ على هامش الأمان الأبيض (**Quiet Zone ≥ 3–4 modules**) حول الرمز وعدم قص الحواف أو وضع نصوص/شعارات تلامس مربعات المسح.
   - ضمان تباين عالٍ بين لون الرمز والخلفية (رمز داكن على خلفية بيضاء أو فاتحة صافية؛ عدم طباعة لون داكن فوق خلفية سوداء بدون مربع أبيض صريح).
   - ألّا يقل المقاس الفعلي للـ QR المطبوع على الكارت عن **22–25 مم** لسرعة القراءة في الإضاءة الضعيفة.
3. **تجربة المسح الفعلي:**
   - مسح الـ QR من نسخة مطبوعة (وليس من الشاشة فقط) باستخدام كاميرا iPhone الافتراضية وكاميرا Android على مسافات قريبة ومتوسطة قبل اعتماد الدفعة.

## 4. قائمة فحص شريحة الـ NFC والكارت الفيزيائي (NFC & Physical Card Checklist)

> ملاحظة: هذه الفحوصات تُنفَّذ يدوياً بعد برمجة الشريحة وطباعة الكارت الفعلي، وليست مختبرة في البرمجيات وحدها.

1. **تطابق سجل الـ NDEF:**
   - كتابة سجل URI واحد مطابق بالضبط للرابط الرسمي (`https://tapp-link.vercel.app/<slug>`) بدون سلاسل تتبع غير مقصودة أو `http://` غير مشفر.
2. **قفل الشريحة أو حمايتها (Locking Policy):**
   - تحديد سياسة الكتابة (Read-Only vs Password-Protected) حسب اتفاق التسليم حتى لا يكتب طرف خارجي رابطاً آخر فوق الشريحة، مع تذكّر أن القفل الدائم لا يمكن التراجع عنه.
3. **اختبار اللمس على أجهزة متعددة:**
   - اختبار المسح على iPhone (من أعلى ظهر الجهاز) وعلى جهازين Android على الأقل (منتصف/أعلى الظهر) والشاشة مفتوحة، وبوجود جراب موبايل عادي.
4. **جودة التشطيب والمواءمة:**
   - التأكد من عمل NFC + QR معاً على نفس الكارت لنفس الوجهة، وفحص وضوح الاسم ومحاذاة الحواف وجودة التغليف قبل التسليم النهائي.

---

## 5. قرار تسليم الكارت النهائي (Final Sign-Off Checklist)

- [ ] نجحت أوامر `bun run lint` و`bun run build` و`bun run check:brands` دون أخطاء.
- [ ] تم فتح الصفحة، نسخ الرابط، مشاركة الصفحة، وتنزيل ملفات QR + `.vcf` (حيث متاح) على هاتف فعلي (iOS + Android).
- [ ] تم اختبار قراءة الـ NFC والـ QR المطبوع على الكارت النهائي نفسه وتأكيد وصولهما لنفس الوجهة الرسمية.
- [ ] تم اعتماد اسم البراند وروابطه الظاهرة مع العميل قبل تسليم الكارت.
